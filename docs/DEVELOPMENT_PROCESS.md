# Development Process

## 새 기능 추가 프로세스

모든 새 기능은 아래 단계를 **순서대로** 거쳐야 합니다.

### 1. 설계 (Design)
- PM이 요구사항 정리
- **보안 연구원이 설계 리뷰** — 인증, 성능, 입력 검증, 공격 벡터 사전 검토
- 설계 승인 후 다음 단계

### 2. 구현 (Implementation)
- 백엔드 개발자가 코드 작성
- TDD: 테스트 먼저 → 구현 → 테스트 통과

### 3. 검증 (Verification)
- **코드 리뷰어**: 타입 안전성, dead code, 패턴 일관성
- **보안 테스트 엔지니어**: 인증/인가, 입력 검증, 정보 노출
- 둘 다 PASS 후 다음 단계

### 4. 승인 (Approval)
- PM이 검증 결과 확인
- 이슈 있으면 2번으로 돌아감
- **PM 승인 없이 커밋 불가**

### 5. 커밋/배포 (Commit)
- 기능별 논리적 커밋
- develop 브랜치 push
- PR 리뷰

```
설계 → 보안 리뷰 → 구현 → 코드 리뷰 + 보안 테스트 → PM 승인 → 커밋
  ↑                                    |
  └──────── 이슈 발견 시 되돌아감 ────────┘
```

## 체크리스트 (커밋 전 필수)

- [ ] 새 엔드포인트에 인증 Guard 적용했는가? (JWT, Roles)
- [ ] WebSocket/실시간 기능에 인증이 있는가?
- [ ] 입력값 검증 DTO가 있는가? (class-validator)
- [ ] 외부 API 호출에 타임아웃/캐싱이 있는가?
- [ ] O(N) 이상 복잡도 연산이 매 요청에 실행되지 않는가?
- [ ] 민감 정보(IP, 토큰)가 로그/응답에 평문 노출되지 않는가?
- [ ] `0.0.0.0/0`, 빈 문자열 등 극단적 입력이 처리되는가?
- [ ] fire-and-forget 패턴에 에러 로깅이 있는가?
- [ ] `npx tsc --noEmit` 통과?
- [ ] `npm test` 전부 통과?
- [ ] E2E 테스트 통과?
